Arquitetura

  • Next.js 16 App Router, React 19, TypeScript estrito e CSS Modules.
  • Supabase Auth/Postgres/Storage; migrations append-only, grants mínimos e RLS.
  • Leituras por read models pequenos; escritas críticas por API, DAL e função SQL privada.
  • Web por HTTPS no IP reservado, com certificado curto e renovação automática; backoffice separado na 3001 e somente em loopback. A aplicação pública ainda depende do primeiro deploy.
  • Release standalone Linux x86_64 reúne código e ambientes do mesmo SHA; symlink atômico, readiness e marcador de recuperação protegem rollback e reboot durante a ativação.

Qualidade e entrega

Cada feature usa branch própria. Antes do merge passam format, lint, tipos, Vitest, banco, documentação, Playwright, build, audit e Knip conforme o risco. Todo PR recebe @codex review, espera real mínima de 60 minutos e novos ciclos depois de cada correção até uma declaração explícita de review limpo no SHA atual.

A análise Knip descobre as specs Playwright por entradas explícitas e não carrega a configuração runtime que exige o ambiente E2E destrutivo; assim, o gate produz o mesmo resultado em um checkout Linux limpo e no Windows de desenvolvimento.

Mutations que carregam e-mail ou senha executam uma única tentativa mesmo sob sinal offline e terminam limpando a referência efêmera; credenciais nunca ficam em uma fila TanStack para reenvio tardio após reconexão.

Merge em main aplica migrations forward-only e publica na VM. Timeout ou serviço indisponível é inconclusivo. Falha pós-merge abre nova branch e repete o ciclo completo.

Princípios operacionais

  • Sem gambiarra em produção; experimento local explícito e reversível é permitido.
  • Uma fonte canônica por fato e documentação sem copiar histórico de execução.
  • Complexidade precisa de requisito, ameaça ou métrica concreta.
  • Playwright prova comportamento visível; unitários e SQL protegem lógica e invariantes.
  • Plano de feature é removido depois do merge/deploy concluído.
