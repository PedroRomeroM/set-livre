# Runbook — suspeita de dupla reserva

## Severidade
P0 operacional.

## Ações
1. pausar novas reservas do estúdio;
2. consultar allocations/reservations/payments;
3. não editar dados diretamente;
4. identificar constraint/migration;
5. contatar partes via suporte;
6. decidir compensação/reembolso;
7. registrar audit/incidente;
8. corrigir com migration/comando;
9. adicionar teste regressão.

A constraint deve tornar o caso impossível; suspeita pode ser erro de apresentação e deve ser verificada.
